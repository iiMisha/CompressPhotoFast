# AGENTS.md Updater

Управление `AGENTS.md` в корне проекта. Детали и структура секций — в `references/AGENTS_TEMPLATE.md` (читать перед выполнением).

## Границы (критично)

- `Write`/`Edit` — только `AGENTS.md`. `Bash` — только read-only `git log`. Не трогать код/настройки, не делать `git commit`, не использовать Task tool — только Glob/Grep/Read (Task(Explore) в этом проекте вызывал переполнение памяти).

## Операции

| Операция | Действие |
|---|---|
| `initialize` | Glob/Grep/Read → создать AGENTS.md по шаблону |
| `update` | `git log -10 --name-only` (или `focus_source`) → правки; проверить размер |
| `add_task` | Задача (макс 15 строк) в «Рабочий процесс» |
| `update_architecture` | Обновить Стек / Архитектура / Инварианты / Актуальный контекст |

## Лаконичность по умолчанию

- Любая новая/изменённая запись пишется максимально лаконично СРАЗУ — не уплотнять задним числом при превышении лимита. Телеграфный стиль: только факты, без вводных оборотов («было добавлено», «в связи с этим»), без нарратива; обоснования — в коммите/логах, не в AGENTS.md.
- Новая запись ≤ 2-3 строк; изменение существующей — в пределах её текущего размера. Максимум информации на токен; если формулировку можно сократить без потери фактов — сокращать.
- Лимит 15000 токенов — предохранитель, а не цель; лаконичность — требование к каждой правке независимо от лимита.

## Лимит размера: ≤ 15000 токенов

- Оценка: `токены ≈ символов / 4` (для русского ≈ символов / 2.5). После ЛЮБОГО изменения проверять (`wc -c AGENTS.md`); при превышении сокращать: старое из «Актуального контекста», неактуальные задачи, описания до essentials.
- Компактность: 1-2 предложения, списки без таблиц, без примеров кода, ссылки на файлы вместо кода, без дублирования.
- Читаемые файлы при анализе — бюджетировать: только ключевые (манифест, `app/build.gradle.kts`, README, точечные Read), не всё сразу.
