# Commit

По умолчанию создать коммит и сразу выполнить `git push origin HEAD` без дополнительного подтверждения. Если пользователь явно просит «только коммит», пуш не выполнять.

## Сообщение

Формат:

```text
<type>(<scope>): <краткое описание>

<необязательное тело>
```

Допустимые `type`: `feat`, `fix`, `refactor`, `perf`, `docs`, `style`, `test`, `build`, `ci`, `chore`.

- Писать по-русски, в нижнем регистре, без точки; предпочитать глагол в совершенном виде или инфинитив.
- Ограничивать первую строку 72 символами.
- Указывать `scope`, только если область однозначна.
- Добавлять тело для нетривиальных исправлений и изменений нескольких модулей; использовать краткий список `-`.

## Workflow

1. Проверить контекст:

   ```bash
   git status
   git diff
   git diff --staged
   git log -5 --pretty=format:"%s"
   ```

2. Включить в анализ и коммит все намеренно изменённые исходники и планы из `.kilo/plans/`. Не исключать план только потому, что он находится в `.kilo`; при необходимости добавить его явным путём.
3. Разделить независимые изменения на отдельные коммиты. Связанные изменения, включая соответствующий план, коммитить вместе. Не смешивать `docs`/`chore` с `feat`/`fix` без необходимости.
4. Определить `type`, `scope`, описание и тело по фактическому diff.
5. Не запускать сборку или тесты: этот skill вызывается после их отдельного выполнения.
6. Выполнить одной цепочкой:

   ```bash
   git add <явные пути>
   git commit -m "<type>(<scope>): <описание>" -m "<тело>"
   git push origin HEAD
   ```

   Для ветки без upstream использовать `git push -u origin HEAD`. При запросе «без пуша» остановиться после `git commit`.
7. Сообщить кратко: сообщение коммита, число файлов, хэш или ссылку и результат push.

## Ограничения

- Не добавлять автоматически генерируемые артефакты (`build/`, `__pycache__/`, `.skill`); планы `.kilo/plans/*.md` являются исключением и включаются, если изменены намеренно.
- Не использовать `--amend` или force-push без явного запроса.
- При обнаружении секретов, токенов, ключей или credential-путей остановиться до коммита и предупредить пользователя.
- Не менять готовое сообщение пользователя без необходимости.
