# Plan: Kilo CLI — предложение ручного pull вместо автозагрузки

## Контекст

В `~/.bashrc` (строки 141–170) есть функция-обёртка `kilo()`: перед запуском CLI выполняется `git fetch --all --prune`; при отставании ветки (behind) и чистом дереве изменения подтягиваются автоматически (`git pull --ff-only`), затем запускается kilo.

Запрос пользователя: при наличии удалённых изменений **не** тянуть их автоматически, а предложить вручную выполнить pull; если пользователь соглашается — выполнить pull и **не запускать** kilo (пользователь перезапустит его сам после просмотра изменений).

## Решения

1. **Prompt вместо автопulla.** При `behind` выводится интерактивный вопрос «Выполнить git pull --ff-only? [y/N]»:
   - **Да** → выполнить `git pull --ff-only`; при успехе напечатать подсказку «изменения подтянуты — перезапустите kilo» и **выйти без запуска kilo** (return 0). При неудаче pull — сообщение об ошибке, тоже без запуска kilo (требуется ручное разрешение).
   - **Нет** (Enter/любое другое) → запустить kilo как обычно.
2. **Грязное дерево.** При `behind` и незакоммиченных изменениях текст вопроса дополняется предупреждением; pull всё равно возможен по явному согласию (git сам откажется при конфликте). Отдельная ветка логики не нужна — `git pull --ff-only` безопасен.
3. **Неинтерактивный запуск.** Если stdin не терминал (`[[ ! -t 0 ]]`), не задавать вопрос — вернуться к текущему поведению (предупреждение + `sleep 2` + запуск kilo). Защита от зависания в скриптах/пайпах.
4. **Без изменений** остаются: логика `ahead` (уведомление + sleep 2), сбой fetch (предупреждение + запуск kilo), тихий запуск при синхронности, `command kilo "$@"` против рекурсии.

## Задачи

1. Отредактировать функцию `kilo()` в `~/.bashrc`, заменив ветку `*behind*` на:

```bash
kilo() {
  if git rev-parse --is-inside-work-tree >/dev/null 2>&1; then
    local status_line msg=""
    if ! git fetch --all --prune --quiet; then
      msg="⚠ git fetch не удался (нет сети?)"
    else
      status_line="$(git status -sb | head -1)"
      case "$status_line" in
        *behind*)
          if [[ -t 0 ]]; then
            local dirty=""
            [[ -n "$(git status --porcelain)" ]] && dirty=" (внимание: есть незакоммиченные изменения)"
            local answer
            read -r -p "↓ $status_line$dirty — выполнить git pull --ff-only? [y/N] " answer
            if [[ "$answer" == y || "$answer" == Y || "$answer" == да ]]; then
              if git pull --ff-only; then
                echo "✓ изменения подтянуты — перезапустите kilo"
              else
                echo "⚠ pull не удался — разрешите конфликт вручную"
              fi
              return 0   # kilo не запускаем
            fi
          else
            msg="↓ $status_line — отстаём от origin (неинтерактивный запуск, pull пропущен)"
          fi
          ;;
        *ahead*)
          msg="↑ $status_line — есть незапушенные коммиты"
          ;;
      esac
    fi
    if [[ -n "$msg" ]]; then
      echo "$msg"
      sleep 2   # задержка, чтобы TUI kilo не затёр сообщение
    fi
  fi
  command kilo "$@"
}
```

2. Проверить синтаксис: `bash -n ~/.bashrc`.
3. Проверить загрузку функции: `bash -ic 'type kilo'`.
4. Обновить заметку для Obsidian в `/tmp/kilo/kilo-git-autofetch-note.md` (новое поведение: prompt, выход без запуска kilo после pull, неинтерактивный fallback) — по желанию пользователя.

## Валидация

- `bash -n ~/.bashrc` — без ошибок.
- `bash -ic 'type kilo'` — функция определена, код совпадает с планом.
- Ручная проверка пользователем в новом терминале: на синхронной ветке — тихий запуск; на behind-ветке — вопрос; `y` → pull и выход; `n`/Enter → запуск kilo.

## Риски и граничные случаи

- `read` в неинтерактивном контексте покрыт проверкой `[[ -t 0 ]]`.
- Дивергенция веток: `--ff-only` откажется, пользователь получит сообщение и разрешит вручную — kilo не запускается, что соответствует запросу.
- Файл `~/.bashrc` вне рабочего пространства проекта — правка требует разрешения на внешнюю директорию (уже редактировался ранее в сессии).
