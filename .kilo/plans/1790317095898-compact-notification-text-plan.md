# План: компактный текст уведомлений без потери информации

## Цель
Сократить длину текста уведомлений/Toast, сохранив все информационные элементы (файл, размеры, экономия, коэффициент, причина). Компактность достигается: короткими единицами размера, удалением пробелов вокруг `→`, компактными разделителями `·`, устранением дублирования между заголовком и текстом.

Решение пользователя: допустимо сократить единицы размера до `4.2М` / `830К` в свёрнутом тексте; в развёрнутом (BigText) оставить полные `МБ/КБ`.

## Текущее состояние (NotificationUtil.kt)
- Свёрнутая статистика мониторинга: `Сжато: N: Сэкономлено X (-45% · 1.8x)` (`formatDailyStats`, строки 554–566).
- Развёрнутая: `Сжато: N\nX → Y\nСэкономлено Z (-45% · 1.8x)`.
- Результат сжатия: `✅ Сжатие фото завершено` / `🖼️ file: 4.2 МБ → 2.3 МБ (-45% · 1.8x)` (strings.xml:51–52).
- Пропуск: `⏭️ Сжатие фото пропущено` / `📱 file: экономия места незначительна (…)` (strings.xml:53–54).
- Toast: `🖼️ file: 4.2 МБ → 2.3 МБ (-45.0%)` (строки 342–377).
- OOM: `Не удалось сжать file. Требуется XMB, доступно YMB.` (строки 785–824).

## Изменения

1. `FileOperationsUtil`: добавить `formatFileSizeCompact(bytes: Long): String` — та же логика, что `formatFileSize`, но без пробела и с единицами `Б/К/М/Г` (например `4.2М`, `830К`). Существующий `formatFileSize` не менять.

2. `NotificationUtil.formatDailyStats`:
   - Свёрнуто: `Сжато: N · −Z (−45% · 1.8x)`, где Z — компактный сохранённый размер (`−` перед размером однозначно означает экономию).
   - Развёрнуто (BigText): `Сжато: N\n4.2МБ → 2.3МБ\nСэкономлено 1.9МБ (−45% · 1.8x)` — полные единицы, слово «Сэкономлено» сохраняется здесь.

3. `showCompressionResultNotification` + strings.xml:
   - Заголовок успеха: `✅ Сжатие завершено` (убрать «фото» — контекст очевиден).
   - Текст успеха: `🖼️ file: 4.2М→2.3М (−45% · 1.8x)` — компактные единицы, без пробелов вокруг `→`.
   - Заголовок пропуска: `⏭️ Сжатие пропущено`.
   - Текст пропуска: `📱 file: выигрыш мал (−45% · 1.8x)` — причина сохранена, формулировка короче.

4. `showCompressionResultToast` (оба варианта): формат как у текста успеха, с `formatFileSizeCompact`; в варианте с процентом округлять до целого (`−45%`) вместо `%.1f` — округление не теряет смысловой информации, точное значение доступно в логах.

5. `showOomErrorNotification`: `file: нужно 48МБ, свободно 12МБ` (убрать «Не удалось сжать» — заголовок уже «Недостаточно памяти»).

6. Обновить `app/src/test/.../NotificationUtilTest.kt` (строки 59–60): проверка `Сэкономлено` переносится на `EXTRA_BIG_TEXT`; для `EXTRA_TEXT` проверять `Сжато: 2` и наличие `−`/`·`.

## Не трогаем
- `formatFileSize` и все использования вне уведомлений (UI, логи).
- ID/каналы уведомлений, приоритеты, действия.
- Строки ошибок в `showErrorNotification` (уже короткие).

## Риски
- Тесты, проверяющие подстроки старых форматов, сломаются — обновляются в п.6.
- Форматирование чисел `String.format` использует локаль: использовать ту же логику, что сейчас (десятичная точка/запятая — консистентно внутри одного формата).

## Валидация
- `./gradlew testDebugUnitTest` (NotificationUtilTest, FileNameProcessingTest).
- `./gradlew assembleDebug`.
- Ручная проверка: свёрнутое и развёрнутое уведомление мониторинга, Toast, уведомления успеха/пропуска/OOM — все поля присутствуют.
