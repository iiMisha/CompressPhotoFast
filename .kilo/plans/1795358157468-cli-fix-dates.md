# План: восстановление EXIF-дат в CLI (команда `fix-dates`)

## Контекст

Android: меню «три точки» → `ExifDateFixWorker` → `ExifDateFixUseCase` — файлам без единой EXIF-даты даты дописываются из источников по приоритету. CLI обязан семантически соответствовать (`AGENTS.md`: «Python-логика должна сохранять семантическое соответствие Android-реализации»).

Семантика Android (`ExifDateFixUseCase.fixAllInner` + `ExifUtil.writeMissingDates`):
- Критерий «есть дата»: `DateTime` (0th) / `DateTimeOriginal` / `DateTimeDigitized` / `GPSDateStamp` — любой из четырёх → файл не трогаем. В CLI уже есть зеркальный `ExifHandler._has_any_date`.
- Источники по приоритету:
  1. имя файла (`FileNameDateParser`) → 3 тега, включая `DateTimeOriginal` (настоящая дата съёмки);
  2. timestamp маркера сжатия (`> 0`, мс) → 2 тега (дата сжатия, не съёмки — `DateTimeOriginal` не выдумывается);
  3. mtime файла → 2 тега (последний fallback).
- HEIC — пропуск (EXIF не пишется на обеих платформах).
- Запись только при полном отсутствии дат (идемпотентно, перепроверка на свежих данных); mtime файла восстанавливается после записи.

## Изменения

### 1. Новый модуль `compressphotofast-cli/src/date_parser.py`

Порт `app/src/main/java/com/compressphotofast/data/FileNameDateParser.kt` (чистые функции, без IO):

- `parse_date_ms(name: Optional[str]) -> Optional[int]` — epoch мс или `None`.
- Шаблоны переносятся 1:1 на `re` (именованные группы `(?P<...>)`; `(?i)` из Kotlin → флаг `re.IGNORECASE`, в Python 3.11+ глобальный inline-флаг не в начале паттерна запрещён):
  1. `EPOCH_PREFIX`: `(?:mmexport|wx_camera_|snapchat-)(\d{13}|\d{16}|\d{19})(?!\d)` — мс/мкс/нс;
  2. basename целиком из цифр (без regex): 13 цифр — мс, 16 — мкс (`/1000`), 10 — с (`*1000`), основа имени без последнего расширения;
  3. `MONTH_NAME` — месяц английскими словами, 4 раскладки (year-first / `Jan 1, 2025` / `01 Jan 2025` / `01Jan2025`), опц. время с `;` вместо `:` и `at`;
  4. `COMPACT_DATETIME` — `20250101123456`, `20250101_123456`;
  5. `SEPARATED_TZ` — `T`/пробел разделитель + суффикс `Z`/`±HH[:MM]` (часы>14 или минуты>59 → `None`); `SEPARATED_DATETIME` — без зоны;
  6. `DAY_FIRST` — `01-02-2025` с разделителями `[-._/]` (+опц. время), DD-MM невалидно → MM-DD;
  7. `DATE_ONLY` — `20250101`, `2025-01-01`.
- Границы `(?<!\d)…(?!\d)` и `(?<!\d[-_.])` — как в Kotlin (Python поддерживает фиксированную ширину).
- Окно валидации: `MIN_VALID_MS = 631_152_000_000` (1990-01-01), max = сейчас + 24 ч (`MAX_FUTURE_WINDOW_MS`).
- Strict-календарь: `datetime(y, m, d, hh, mm, ss)` — `ValueError` (31 февраля, месяц 13, час 29) → `None`; локальная зона — naive `int(dt.timestamp() * 1000)`; TZ-суффикс — `timezone(timedelta(...))` со знаком.
- `from_digit_runs`: вырезать разделители `[_\-. T:]`, длина цифр ∈ {8, 12, 14}.
- Намеренно НЕ парсится (как в Android): 2-значные годы, русские месяцы, слитный/пробельный day-first, прогоны 9/11–12/15/17–18/19+ цифр без префикса, счётчики (`DSC01234`).

### 2. `ExifHandler.write_missing_dates` в `exif_handler.py`

Новый статический метод — обобщение существующего `backfill_missing_dates`:

```python
write_missing_dates(file_path: str, date_source_ms: int,
                    include_datetime_original: bool) -> bool
```

- Структура как у `backfill_missing_dates`: захват atime/mtime до записи → повторная проверка `_has_any_date` (есть даты → `True`, no-op) → запись → `os.utime` восстановление при успехе.
- Пишет `DateTime` (0th) + `DateTimeDigitized` (Exif) [+ `DateTimeOriginal` при флаге] из `datetime.fromtimestamp(date_source_ms / 1000).strftime("%Y:%m:%d %H:%M:%S")` (локальная зона — как существующий код).
- PNG — через eXIf-чанк (`_write_exif_to_png`), JPEG — `piexif.insert`, HEIC — `False`.
- Рефакторинг без смены поведения: `backfill_missing_dates(file_path)` становится обёрткой `write_missing_dates(file_path, int(mtime_ms), False)` (mtime из stat).

### 3. Воркер `process_single_file_date_fix` в `multiprocessing_utils.py`

По образцу `process_single_file`. Сигнатура: `(file_info, dry_run) -> (file_info, status, source, date_str, error)`; статусы: `fixed` / `already_ok` / `heic` / `no_source` / `failed`; `source` ∈ {`filename`, `marker`, `mtime`, `""}.

Логика (паритет `fixAllInner`):
1. `ExifHandler.is_heic_file` → `heic`.
2. `read_exif_data`: `None` — не «сбой» (PNG без eXIf-чанка / JPEG без EXIF — легитимный случай «нет дат»), работать с пустым dict `{"0th": {}, "Exif": {}}`.
3. `_has_any_date` → `already_ok`.
4. Приоритет источников: `parse_date_ms(file_info.name)` (3 тега) → маркер `get_compression_info` c `timestamp > 0` (2 тега) → mtime из `file_info.mtime` (2 тега; `<= 0` → `no_source`).
5. `dry_run=True` — только вычислить `source`/`date_str`, ничего не писать.
6. Любое исключение → `failed` с сообщением (битый файл проявится здесь же).

### 4. Команда `fix-dates` в `cli.py`

```
compressphotofast fix-dates PATH [options]
```

- `PATH` — файл или папка (как `compress`); скан через `find_image_files(recursive=True)` с дефолтными фильтрами (`MIN_FILE_SIZE=0`, `MAX_FILE_SIZE`, `skip_app_dir=True`, HEIC `_compressed` отсечён сканом).
- Опции: `--skip-screenshots/-s`, `--skip-messenger/-m`, `--dry-run/-n`, `--yes/-y`.
- Panel с настройками + подтверждение `click.confirm` (как `compress`), `--yes` пропускает.
- `ProcessPoolExecutor` (spawn, `os.cpu_count()`) + Rich `Progress` — по образцу `_run_compression`; `KeyboardInterrupt` → частичный итог.
- Итоговая таблица: Scanned / Fixed / Already have dates / HEIC skipped / No source / Failed. В dry-run — таблица планов (имя, источник, дата).

## Решения и границы

- Только CLI: Android-код не меняется, APK не собирается/не публикуется.
- Счётчики `already_ok`/`heic` — расширение Outcome Android (там такие файлы молча `continue`) для наглядного итога CLI; семантика обработки не меняется.
- `no_source` в Android = нечитаемый EXIF; в CLI нечитаемый/битый файл попадает в `failed` на записи, а `None` от `read_exif_data` = «нет EXIF» → даты пишутся.
- Timestamp маркера — миллисекунды (CLI пишет `int(now*1000)`), проверка `> 0`.
- Маркер-источник приоритетнее mtime, имя файла приоритетнее маркера — строго как в Android.

## Риски

- Регексы Kotlin→Python: `(?i)` не в начале паттерна запрещён в Python 3.11+ — использовать `re.IGNORECASE`; именованные группы `(?P<...>)`; портированные тесты из `FileNameDateParserTest.kt` снимают риск расхождения.
- `piexif.insert` на JPEG без EXIF создаёт APP1 с нуля — подтверждено существующим `backfill_missing_dates`.

## Валидация

1. `pytest compressphotofast-cli/tests/` — все существующие + новые зелёные.
2. Ручная проверка: временная папка с JPEG без дат (`mmexport...jpg`, `2025-01-02 10-20-30.jpg`, бездатовый), PNG, HEIC → `fix-dates` → проверить теги (piexif) и сохранность mtime; повторный запуск — все `already_ok`.
3. `./gradlew assembleDebug` не требуется (Android не меняется).
