# CompressPhotoFast CLI

Быстрый инструмент для сжатия изображений в командной строке. Работает на Linux, Windows и macOS.

## 🚀 Установка и использование

### Способ 1: Автоматическая установка (рекомендуется)

> **Что это:** Один скрипт сам установит Python, все зависимости и настроит программу. Ничего делать вручную не нужно.

#### Linux/macOS

Откройте терминал и выполните:

```bash
cd compressphotofast-cli
./install/install.sh
```

**Что произойдет:**
- Скрипт проверит, установлен ли Python 3.10+
- Если нет — предложит установить автоматически
- Установит системные зависимости для работы с HEIC фото (с iPhone)
- Создаст виртуальное окружение
- Установит программу

#### Windows

Откройте PowerShell и выполните:

```powershell
cd compressphotofast-cli
.\install\install.ps1
```

**Что произойдет:**
- Скрипт проверит, установлен ли Python 3.10+
- Если нет — предложит установить автоматически через winget или chocolatey
- Создаст виртуальное окружение
- Установит программу

---

### Способ 2: Простая установка через launcher

> **Что это:** Просто запустите программу — она сама установится при первом запуске. Требуется только Python.

#### Linux/macOS

```bash
cd compressphotofast-cli
./compressphotofast.sh --help
```

При первом запуске автоматически создастся виртуальное окружение и установятся все зависимости.

#### Windows

```powershell
cd compressphotofast-cli
.\compressphotofast.bat --help
```

## ✨ Возможности

- 🖼️ **Поддержка форматов**: JPEG, PNG, **HEIC/HEIF** (с конвертацией в JPEG)
- ⚡ **Многопроцессорность**: Автоматическое использование всех ядер CPU
- 🎯 **Сжатие как в Android**: Фиксированные пресеты качества, паритет с мобильным приложением
- 💾 **Сохранение EXIF**: Полное сохранение метаданных
- 🔄 **Безопасность**: Бэкапы и блокировки при замене файлов
- 📊 **Статистика**: Детальная отчетность о сжатии
- 🗓️ **Восстановление дат**: Дописывание EXIF-дат из имени файла, маркера или mtime (`fix-dates`)

## 📖 Как использовать

### После установки

После установки используйте **launcher-скрипты** для запуска:

**Linux/macOS:**
```bash
cd compressphotofast-cli
./compressphotofast.sh compress ~/Photos
```

**Windows:**
```powershell
cd compressphotofast-cli
.\compressphotofast.bat compress C:\Photos
```

> **Примечание:** Launcher-скрипты автоматически создадут виртуальное окружение при первом запуске, если вы использовали Способ 2.

### Примеры использования

```bash
# Сжать папку с фотографиями
compressphotofast compress ~/Photos

# Сжать один файл
compressphotofast compress photo.jpg

# Сжать HEIC фото с iPhone (автоматически конвертируются в JPEG)
compressphotofast compress ~/Pictures/iPhone

# Посмотреть статистику по папке
compressphotofast stats ~/Photos

# Восстановить отсутствующие EXIF-даты
compressphotofast fix-dates ~/Photos --yes

# Высокое качество, замена оригиналов
compressphotofast compress ~/Photos -q high -r

# Тестовый режим (без фактического сжатия)
compressphotofast compress ~/Photos --dry-run
```

## Команды

### `compress` — Сжатие изображений

```bash
compressphotofast compress [ПУТЬ] [ОПЦИИ]
```

**Опции:**

| Опция | Короткая | Описание |
|-------|----------|----------|
| `--quality` | `-q` | Качество: `low` (60), `medium` (70), `high` (80), `auto` (= 70) (по умолчанию: `medium`) |
| `--replace` | `-r` | Заменить оригинальные файлы |
| `--output-dir` | `-o` | Папка для сохранения сжатых файлов |
| `--skip-screenshots` | `-s` | Пропустить скриншоты |
| `--skip-messenger` | `-m` | Пропустить фото из мессенджеров |
| `--force` | `-f` | Пересжать уже сжатые файлы |
| `--dry-run` | `-n` | Показать что будет сжато без фактического сжатия |

**Примеры:**

```bash
# Высокое качество, замена оригиналов
compressphotofast compress ~/Photos -q high -r

# Сохранить в отдельную папку
compressphotofast compress ~/Photos -o ~/Compressed

# Тестовый режим
compressphotofast compress ~/Photos -n

# Пропустить скриншоты и мессенджеры
compressphotofast compress ~/Photos -s -m
```

### `stats` — Статистика

```bash
compressphotofast stats [ПУТЬ] [ОПЦИИ]
```

Показывает количество изображений, общий размер и процент сжатых файлов.

**Примеры:**

```bash
compressphotofast stats ~/Photos
compressphotofast stats ~/Photos -s -m
```

### `fix-dates` — Восстановление EXIF-дат

```bash
compressphotofast fix-dates [ПУТЬ] [ОПЦИИ]
```

Файлам без единой EXIF-даты (`DateTime`, `DateTimeOriginal`, `DateTimeDigitized`, `GPSDateStamp`) даты дописываются по приоритету источников — как в Android-приложении:

1. **Имя файла** — дата съёмки из имени (`mmexport…`, `IMG_20250101_123456`, `2025-01-02 10-20-30`, месяцы словами и др.) → 3 тега, включая `DateTimeOriginal`
2. **Маркер сжатия** — timestamp из EXIF-маркера CompressPhotoFast → 2 тега
3. **mtime файла** — дата модификации (последний fallback) → 2 тега

Запись идемпотентна (файлы с датами не трогаются), mtime файла сохраняется. HEIC пропускается (EXIF не пишется).

**Опции:**

| Опция | Короткая | Описание |
|-------|----------|----------|
| `--skip-screenshots` | `-s` | Пропустить скриншоты |
| `--skip-messenger` | `-m` | Пропустить фото из мессенджеров |
| `--dry-run` | `-n` | Показать план без записи (имя, источник, дата) |
| `--yes` | `-y` | Пропустить подтверждение |

**Примеры:**

```bash
# Восстановить даты во всей папке
compressphotofast fix-dates ~/Photos --yes

# Посмотреть, что и откуда будет дописано
compressphotofast fix-dates ~/Photos -n

# Один файл
compressphotofast fix-dates photo.jpg -y
```

### `version` — Версия

```bash
compressphotofast version
```

## Как это работает

- **Обрабатываются файлы**: от 50 КБ до 100 МБ (фильтр на этапе скана, как в Android)
- **Минимальный размер для сжатия**: 100 КБ
- **Минимальная экономия**: 30% + 10 КБ
- **EXIF-маркеры**: Добавляет метку сжатия для отслеживания
- **Уровни качества**: Low (60), Medium (70), High (80)
- **Автоматический режим** (`-q auto`): фиксированное качество Medium (70) — паритет с Android, без перебора

## Поддержка форматов

### Поддерживаемые форматы:

| Формат | Чтение | Запись | Примечания |
|--------|--------|--------|------------|
| JPEG | ✅ | ✅ | Полная поддержка |
| PNG | ✅ | ✅ | Полная поддержка |
| HEIC/HEIF | ✅ | ✅ → JPEG | Конвертируется в JPEG с сохранением EXIF |

### HEIC/HEIF поддержка

**Что такое HEIC?**
HEIC (High Efficiency Image Container) — формат, используемый по умолчанию на iPhone и устройствах Apple с iOS 11+.

**Как обрабатываются HEIC файлы:**

1. **Автоматическая конвертация**: HEIC файлы конвертируются в JPEG для максимальной совместимости
2. **Сохранение качества**: Оригинальное разрешение и EXIF метаданные полностью сохраняются
3. **Выходное расширение**: `.heic` файлы сохраняются как `.jpg`
4. **Пропуск с пометкой**: если сжатие не даёт экономии, EXIF-маркер в HEIC записать нельзя, поэтому файл переименовывается: `photo.heic` → `photo_compressed.heic`. Такой файл исключается из дальнейшей обработки (паритет с Android-приложением). Учтите, что имя файла на диске меняется.

**Требования для HEIC поддержки:**

- **Linux**: Требуется установка `libheif-dev`
- **Windows**: Работает из коробки (precompiled wheels)
- **macOS**: Требуется установка `libheif` через Homebrew

**Примеры:**

```bash
# Сжать HEIC файлы с iPhone
compressphotofast compress ~/Pictures/iPhone/Photos

# HEIC файлы будут конвертированы в JPEG:
# photo.heic → photo_compressed.jpg
```

**Примечание**: Если HEIC поддержка не установлена, файлы `.heic` и `.heif` будут пропущены с предупреждением.

## Multi-Core поддержка

CLI версия автоматически использует все доступные ядра процессора для параллельной обработки изображений.

### Особенности:

- **Автоопределение процессов**: Количество процессов определяется автоматически как `os.cpu_count()`
- **Параллельная обработка**: Изображения обрабатываются одновременно в отдельных процессах
- **Process-safe операции**: Безопасная работа с файлами через `multiprocessing.Manager().Lock()`
- **Асинхронный вывод**: Результаты отображаются по мере готовности (не по порядку)
- **Обработка ошибок**: Ошибка одного файла не останавливает обработку остальных

### Производительность:

Примерное ускорение обработки в **N раз**, где N — количество ядер процессора (для CPU-bound задач).

**Примеры производительности:**
- 8 ядер CPU: ~8x ускорение для большого количества файлов
- 30 файлов (3.4 МБ): ~2.5 секунды (vs ~20 секунд последовательно)
- Эффективность зависит от баланса CPU/I/O операций

### Технические детали:

- Используется `concurrent.futures.ProcessPoolExecutor` с контекстом `spawn`
- Process-safe сбор статистики через `ProcessSafeStats` с `multiprocessing.Manager().Lock()`
- PIL/Pillow освобождает GIL во время операций с изображениями
- Каждый процесс обрабатывает файл независимо

## Устранение проблем

### Ошибка "externally-managed-environment"

**Симптом**: При установке появляется ошибка:
```
error: externally-managed-environment
To install package system-wide, try apt install python3-xyz
```

**Причина**: Начиная с Python 3.12+, системный Python защищен от прямой установки пакетов (PEP 668).

**Решение**: Используйте виртуальное окружение:

```bash
# Создание виртуального окружения
python3 -m venv venv

# Активация (Linux/macOS)
source venv/bin/activate

# Активация (Windows)
.\venv\Scripts\Activate.ps1

# Установка пакета в виртуальное окружение
pip install --upgrade -e .
```

### HEIC файлы не обрабатываются

**Симптом**: Файлы `.heic` пропускаются с предупреждением

**Решение**:

```bash
# Убедитесь, что виртуальное окружение активировано
source venv/bin/activate  # Linux/macOS
# или
.\venv\Scripts\Activate.ps1  # Windows

# Linux
sudo apt-get install libheif-dev libffi-dev
pip install --upgrade pillow-heif

# Windows
pip install --upgrade pillow-heif

# macOS
brew install libheif
pip install --upgrade pillow-heif
```

### Ошибка "cannot identify image file"

**Причина**: Файл поврежден или формат не поддерживается

**Решение**: Проверьте файл и убедитесь, что это изображение поддерживаемого формата

### Медленная обработка

**Причина**: Большое количество маленьких файлов

**Решение**: Файлы меньше 50 КБ пропускаются автоматически на этапе скана; сжатие выполняется только для файлов от 100 КБ. Отдельная настройка не требуется.
